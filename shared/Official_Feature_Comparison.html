Feature comparison: Shadertoy · FragCoord · Shader Workshop

Capability matrix for people choosing a shader playground or runtime. Ratings describe support for that feature, not overall product quality.

Meaning
🟢Yes Yes — solid, first-class support
🟡Partial Partial — present but limited, awkward, incomplete, or unreliable
🔴No No — not offered in a useful form

Columns: Shadertoy.com · FragCoord.xyz · Shader Workshop (offline C/C++ app; CPU software rendering via PortableGL)

Ratings prefer first-hand product knowledge and public docs (including FragCoord’s changelog, current through v1.3.2, August 2026). Where something is still unknown (e.g. FragCoord audio-only export), it is marked —— rather than guessed.

Core rendering

Feature Shadertoy FragCoord Shader Workshop
Image pass (mainImage / equivalent) 🟢Yes 🟢Yes 🟢Yes
Multipass buffers (A–D style) 🟢Yes 🟢Yes 🟢Yes
Float multipass storage (e.g. RGBA32F) 🟢Yes 🟢Yes 🟢Yes
Independent per-pass resolution 🟡Partial 🟢Yes 🟢Yes
Whole-buffer / full-frame control (CPU SIMD, custom frame loop) 🔴No 🔴No 🟢Yes
Built-in pass recursion (N iterations per frame) 🔴No 🟢Yes 🟢Yes
Multiple render targets (MRT) 🔴No 🟢Yes 🔴No
GPU compute passes 🔴No 🟢Yes 🔴No
Writable 1D / volume pass buffers 🔴No 🟢Yes 🔴No

Notes

  • Shadertoy buffers are high-precision float; Image is 8-bit. Per-pass size is not free-form like dedicated tools (hence 🟡).
  • FragCoord 32-bit float pass formats are documented since 0.7.1 / 0.8 (changelog); HTML export and WebGPU honor float buffers and u_main feedback.
  • Whole-buffer control is a CPU-app idea (mainFrame in Workshop). FragCoord’s recursion is separate and listed on its own row — not the same as a host-side frame pointer / SIMD loop. FragCoord compute (WebGPU; switch a pass between Fragment and Compute) is GPU compute, not mainFrame.
  • FragCoord MRT (fragColor1 / fragData[i], sample via u_passN_outL) and 1D / cubemap / volume pass buffers shipped in 1.3 Output; non-2D buffers and MRT are Pro. WebGL HTML export still blocks non-2D buffers and MRT (use Embed or GLSL).
  • Workshop: PASS_FMT_RGBA32F / per-pass scale·absolute via set_pass_config; mainFrame; pass_config.recursion + u_recursion / u_max_recursion. No MRT, no GPU compute, no writable 1D/volume passes.

Audio

Feature Shadertoy FragCoord Shader Workshop
Procedural sound-out (mainSound) 🟢Yes 🔴No 🟢Yes
Music / analysis texture (classic 512×2 FFT + wave) 🟢Yes —— 🟢Yes
Always-on audio history (512×512 spectrogram) 🔴No 🟢Yes 🟢Yes
Microphone input 🟢Yes 🟢Yes 🟢Yes
Live post-mix / “what you hear” analysis 🔴No —— 🟢Yes

Notes

  • Shadertoy mainSound is precomputed; Workshop streams. FragCoord does not document Shadertoy-style mainSound.
  • FragCoord u_audio is documented as a 512×512 history (weighted FFT / waveform / raw FFT). Sources: mic, file, URL, or webcam, with a redesigned tuner/playbar. Workshop provides the same class of feature as always-on u_audio (device postmix) and Shadertoy-style 512×2 channel textures for ports.
  • “—” for FragCoord classic 512×2 / post-mix: not scored as missing product features without clear docs; they may fold audio into u_audio only.

Video, camera & capture

Feature Shadertoy FragCoord Shader Workshop
Webcam 🟢Yes 🟢Yes 🟢Yes
Screen capture as input 🔴No 🟢Yes 🟢Yes
Video file textures 🟢Yes 🟢Yes 🟢Yes
Built-in freefly camera uniforms 🔴No 🟢Yes 🟢Yes

Notes

  • FragCoord: live webcam or screen capture or a video file as a feed (redesigned u_webcam tuner: play/pause and seek for video sources). Workshop: separate WEBCAM and SCREENCAP channels (primary display; FPS / resolution prefs).
  • Freefly: FragCoord u_camera_pos / u_camera_dir plus gamepad camera controls (1.3); Workshop adds u_camera_view and freefly prefs (keyboard + mouse).
  • FragCoord video (and other media) is configured via the sampler / input UI: URL load plus a catalog of presets, with tabs filtered by sampler type (sampler2D vs 3D, etc.).

Inputs & media

Feature Shadertoy FragCoord Shader Workshop
Keyboard 🟢Yes 🟢Yes 🟢Yes
Mouse (position / click / drag style) 🟢Yes 🟢Yes 🟢Yes
Cubemap textures (static assets) 🟢Yes 🟢Yes 🟢Yes
Procedural cubemap pass (CubeA / mainCubemap) 🟢Yes 🟢Yes 🔴No
3D volume textures 🟢Yes 🟢Yes 🟢Yes
Custom local / URL media 🟡Partial 🟢Yes 🟢Yes
Previous-canvas feedback without a free buffer (u_main) 🟡Partial 🟢Yes 🟢Yes

Notes

  • Shadertoy keyboard is a channel texture; FragCoord and Workshop expose keyboard without using a channel slot (Workshop: always-on array).
  • Shadertoy previous-frame feedback is usually buffer self-bind (🟡 vs dedicated previous-main). FragCoord/Workshop: u_main (Workshop also under recursion). FragCoord 1.3.1 fixed ping-pong / u_main export and thumbnail capture.
  • FragCoord media: URL grab (similar idea to Workshop custom loads) and a built-in catalog in the sampler configuration panel (1.3: hide tiles, favorites, Poly Haven and procedural textures). Equirectangular cubemaps upload on WebGPU. CubeA-style cubemap pass buffers are now first-class on FragCoord (1.3, Pro for non-2D).
  • Workshop still has no procedural cubemap pass (static cubemap assets and sampling only).

Audio-only export 🔴No —— 🟢Yes

In-browser GLSL (or multi-lang) editor 🟢Yes 🟢Yes 🔴No
Offline native app / local binaries 🔴No 🔴No 🟢Yes
CPU software path (no GPU required to run) 🔴No 🔴No 🟢Yes

Notes

  • Shadertoy time/resolution controls and export are more limited than dedicated tools.
  • FragCoord: strong time/resolution control (1.3.2: click timeline to play/pause, drag to seek; viewport W×H lock including Square), export to several targets (WebGL HTML, Shadertoy, HLSL, Metal, WGSL, SKSL, Slang, Golf), Tuner. Video export includes audio, loop settings, live WebM capture, and a code overlay option. Audio-only export not rated without confirmation. PWA install exists; still not a native offline binary.
  • Workshop: C/C++ shaders as shared libraries + do_user_gui — not an in-app GLSL editor by design. MP4 (with audio) and audio-only export.

Analysis, community & niche

Feature Shadertoy FragCoord Shader Workshop
Expression inspect / intermediate visualization 🔴No 🟢Yes 🔴No
NaN / Inf / OOR pixel flags 🔴No 🟢Yes 🔴No
Instruction / cost heatmap 🔴No 🟢Yes 🔴No
Frame-time history graph 🔴No 🟢Yes 🟢Yes
Social explore / likes / publish 🟢Yes 🟢Yes 🔴No
SoundCloud integration 🔴No 🟢Yes 🔴No
VR pass (mainVR) 🟢Yes 🔴No 🔴No
Shared “Common” / snippet library 🟢Yes 🟢Yes 🟡Partial
MIP-mapped sampling modes 🟢Yes 🟢Yes 🟡Partial

Notes

  • FragCoord’s inspector suite (Tuner, Inspect, Errors, Frames / Speed tab, Heatmap) is a core product differentiator (Xor’s overview). Later changelog items: rebuilt Inspect, Speed tab with per-pass GPU time, heatmap memory estimates, HDR / u_color_gamut.
  • Workshop Speed tab is a first-class frame-time graph (shader-work ms, hover samples, click-to-pause, 64/128/256 window, FPS-budget line). Debug tooling is otherwise normal C tooling, not expression recompile. NaN overlay and tile heatmap are still open.
  • SoundCloud on Shadertoy: integration has been broken for years after SoundCloud API changes (community reports and related tools cite the same breakage). Rated 🔴 as not useful in practice, even if UI remnants remain. FragCoord added working SoundCloud-driven audio-reactive shaders in 0.9.1 (proxy + redesigned audio picker). Workshop never offered it.
  • Workshop “Common” is headers / #include rather than a web Common tab (🟡 = different model, not “broken”). FragCoord’s Common tab plus a community snippet library (save / share / autocomplete).
  • MIP modes: Shadertoy and FragCoord both support MIP/filter configuration for samplers (FragCoord also mips float buffers). Workshop builds a real mip chain for static 2D textures and cubemaps (channel checkbox / texture_settings.mipmap; texture2DLod / texture2DGrad when automatic derivatives are unavailable). Ignored for volumes, video, audio, buffers, webcam, and screen capture — hence 🟡, not 🟢.

How to read this

Product Best thought of as…
Shadertoy Reference community GLSL multipass site (buffers, CubeA, social); some integrations (e.g. SoundCloud) are effectively dead.
FragCoord Browser analysis / authoring IDE (inspect, heatmap, tuner, recursion, camera, full media catalog + URLs, u_audio, MRT / compute / non-2D buffers, export). Several 1.3 buffer features are Pro.
Shader Workshop Offline C/C++ runtime: multipass/float/res, media (video, volumes, mic, webcam, screen), freefly, recursion, u_main / u_audio, mipmapped static textures, Speed-tab frame graph, export — no GPU required.

Still unscored (avoid guessing)

  • FragCoord audio-only export (video+audio is confirmed; a standalone audio file is not)
  • Exact parity of every asset catalog item across products

Ratings reflect product capability as understood August 2026 (Shader Workshop mipmaps + Speed-tab graph; FragCoord through changelog 1.3.2). Products change; corrections welcome via the issue tracker.
